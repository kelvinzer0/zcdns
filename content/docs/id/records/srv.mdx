# SRV Record

SRV Record adalah DNS record yang menentukan hostname dan port untuk layanan tertentu, memungkinkan aplikasi menemukan layanan secara otomatis.

## Apa itu SRV Record?

SRV (Service) Record menyediakan informasi tentang layanan yang tersedia dalam domain, termasuk hostname, port, priority, dan weight untuk load balancing.

## Format SRV Record

```
Name: _service._protocol.domain
Type: SRV
Priority: 10
Weight: 5
Port: 443
Target: server.example.com
TTL: 3600
```

## Komponen SRV Record

### Service Name
```
_service._protocol.domain
```
- **_service**: Nama layanan (contoh: _http, _sip, _xmpp)
- **_protocol**: Protokol transport (_tcp atau _udp)
- **domain**: Domain yang menyediakan layanan

### Priority
```
Priority: 10
```
- Angka 0-65535
- **Angka lebih kecil = prioritas lebih tinggi**
- Client coba server priority rendah dulu

### Weight
```
Weight: 5
```
- Load balancing untuk server dengan priority sama
- **Angka lebih besar = lebih sering dipilih**
- 0 = server backup

### Port
```
Port: 443
```
- Port number tempat layanan berjalan
- 1-65535

### Target
```
Target: server.example.com
```
- Hostname server yang menyediakan layanan
- Harus FQDN (Fully Qualified Domain Name)

## Contoh Penggunaan SRV Record

### HTTP/HTTPS Services
```
_http._tcp.example.com SRV 10 5 80 web1.example.com
_https._tcp.example.com SRV 10 5 443 web1.example.com
```

### Email Services (SMTP)
```
_smtp._tcp.example.com SRV 10 5 25 mail.example.com
_submission._tcp.example.com SRV 10 5 587 mail.example.com
```

### VoIP Services (SIP)
```
_sip._tcp.example.com SRV 10 5 5060 sip1.example.com
_sip._udp.example.com SRV 10 5 5060 sip1.example.com
```

### XMPP/Jabber
```
_xmpp-client._tcp.example.com SRV 10 5 5222 xmpp.example.com
_xmpp-server._tcp.example.com SRV 10 5 5269 xmpp.example.com
```

### Minecraft Server
```
_minecraft._tcp.example.com SRV 10 5 25565 mc.example.com
```

## Load Balancing dengan SRV Record

### Priority-based (Failover)
```
_http._tcp.example.com SRV 10 0 80 primary.example.com
_http._tcp.example.com SRV 20 0 80 backup.example.com
```

### Weight-based (Load Distribution)
```
_http._tcp.example.com SRV 10 60 80 server1.example.com
_http._tcp.example.com SRV 10 40 80 server2.example.com
```

### Combined Priority + Weight
```
# Primary servers (priority 10)
_http._tcp.example.com SRV 10 50 80 primary1.example.com
_http._tcp.example.com SRV 10 50 80 primary2.example.com

# Backup servers (priority 20)  
_http._tcp.example.com SRV 20 100 80 backup.example.com
```

## Cara Membuat SRV Record

1. Login ke DNS management panel
2. Pilih "Add Record"
3. Pilih type "SRV"
4. Masukkan service name (_service._protocol)
5. Masukkan priority, weight, port
6. Masukkan target hostname
7. Atur TTL
8. Simpan record

## Service Discovery Process

1. **Client Query**: Aplikasi query SRV record untuk layanan
2. **DNS Response**: DNS return list server dengan priority/weight
3. **Priority Selection**: Client pilih server dengan priority tertinggi
4. **Weight Calculation**: Jika ada multiple server dengan priority sama, gunakan weight
5. **Connection**: Client connect ke server terpilih

## Best Practices SRV Record

### Naming Convention
- Gunakan standard service names (_http, _https, _sip)
- Konsisten dengan protokol (_tcp vs _udp)
- Dokumentasikan custom service names

### Priority Planning
- **Primary services**: Priority 10
- **Secondary services**: Priority 20, 30
- **Emergency backup**: Priority 100

### Weight Distribution
- Distribusi berdasarkan kapasitas server
- Server powerful = weight lebih tinggi
- Monitor actual load distribution

### Redundancy
- Selalu sediakan backup server
- Test failover secara berkala
- Monitor health semua server

## Troubleshooting SRV Record

### Verifikasi SRV Record
```bash
nslookup -type=SRV _http._tcp.example.com
dig _http._tcp.example.com SRV
```

### Test Service Discovery
```bash
# Check specific service
dig _sip._tcp.example.com SRV

# Check all SRV records for domain
dig example.com ANY | grep SRV
```

### Masalah Umum

#### Service Not Discovered
- **Check**: SRV record format benar
- **Verify**: Target hostname resolve ke IP
- **Test**: Port accessible di target server

#### Load Balancing Tidak Merata
- **Check**: Weight calculation
- **Monitor**: Actual traffic distribution
- **Adjust**: Weight values berdasarkan monitoring

#### Failover Tidak Berfungsi
- **Check**: Priority values
- **Test**: Primary server down scenario
- **Verify**: Client support SRV failover
